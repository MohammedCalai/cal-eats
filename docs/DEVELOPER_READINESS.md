## Onboarding and routine checks

1. Obtain named, least-privileged repository access from the Cal-Eats owner. Use a feature branch and the pinned Node 24.19.0 / npm 11.17.0 toolchain. Never share credentials in issues or documentation.
2. Install with `npm ci --ignore-scripts`. Dependency versions remain unchanged by this batch.
3. Run `npm run check:developer`. It clears inherited application/provider/build configuration in its child processes, selects local simulation and local mail, and runs core plus native tests, both native type checks, the portal build and packaging checks. It does not load `.env`, start the API, migrate existing data or contact providers. Tests use synthetic fixtures.
4. For local application development, follow the root local setup with an explicitly new database path and fictional data. `npm start` still applies migrations unless `CALAI_MIGRATE_ON_START=false`; do not point local development at a restaurant or production database.
5. Use the [operations runbook](OPERATIONS_RUNBOOK.md) for read-only database preflight, backup/restore validation, staged release checks and rollback. Keep secrets outside Git and Docker context.

The GitHub workflow uses [checkout](https://github.com/actions/checkout) and [setup-node](https://github.com/actions/setup-node), pinned to the resolved v4 commits. It uses pull-request workflows rather than `pull_request_target`, disables persisted checkout credentials and grants only `contents: read`. Branch protection/access settings were not changed by this batch.

## Work still blocking production or scale claims

- **Printing:** PP-01 remains open. A bridge can resume an expired claim after another device receives it. A complete fix needs a jointly versioned dispatch-ownership protocol, durable device outcomes and a coordinated API/bridge rollout. Merely rejecting a stale acknowledgement or checking a local expiry before sending is not sufficient. Keep physical changes out of this batch; require two-device, lost-acknowledgement, power-loss and paper-out tests.
- **Money:** provider-originated refund/dispute reconciliation and held-transfer recovery remain open. Preserve all payment and weekly payout rules; use reviewed sandbox cases before any live change.
- **Capacity:** discovery query shape/indexes, unbounded reads, polling load and worker scheduling remain open. No 10,000-business capacity is certified. Use the measured [scalability plan](audit-2026-10-30/SCALABILITY.md) in isolated staging.
- **Security:** account-recovery delivery, privileged step-up/MFA, trusted-proxy limits, bounded hashing queues, key rotation and expanded tenant-negative tests remain open. The Calai reference stream remains unsuitable for integration until tenant authentication is reviewed and fixed by its owner.
- **Operations:** migration SQL checksums, deployment compatibility rehearsal, worker/queue/disk telemetry, alert routing, key escrow, protected off-host backups, recovery timings and physical Surface testing still need named owners and evidence.
- **Dependencies:** the dated audit advisories require reachability review and separately tested updates. This batch does not upgrade dependencies or claim those advisories are resolved.
