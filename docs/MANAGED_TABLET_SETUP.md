# Connect a Cal-Eats tablet through Intune

The Cal-Eats system administrator opens **Tablets**, chooses the Windows device from the Microsoft directory, selects the business and **Calai**, **Cal-Eats** or **Both**, then saves. The business must already have each selected product linked and active. A new tablet with an eligible Cal-Eats location starts its first connection from this Save. For a Calai-only business, the verified owner approves the assigned tablet once in **Accounts & connections**. A registered tablet receives later choices through its existing signed connection.

The pending state covers Intune assignment and device check-in. Microsoft check-in timing varies. Registration requires matching evidence from the managed device and fresh proof of its protected Windows key. The current app choice is shown as received only after the connected business workspace acknowledges the saved revision. The acknowledgement covers the Cal-Eats business workspace. Remember that Calai tenant creation opens the existing separate Calai admin, and access to native Calai data requires the restaurant’s existing verified owner approval for the tablet.

## One-time pilot configuration

Keep `CAL_EATS_MANAGED_SETUP_ENABLED=false` until Microsoft administrator consent and the exact device have been reviewed. The existing Intune directory reader keeps its own certificate and permissions. Configure a separate Microsoft app certificate for the managed setup connection. Its application permissions are `DeviceManagementScripts.ReadWrite.All`, `DeviceManagementManagedDevices.Read.All`, `GroupMember.Read.All` and `Device.Read.All`. Microsoft grants script write tenant-wide. Cal-Eats checks the target against a server-side allowlist and independently verifies the Intune device, Entra device object and isolated group before assignment. It creates a dedicated Cal-Eats script per first connection. Existing group memberships, scripts and device sync schedules are outside this connection’s job.

In `CAL_EATS_MANAGED_SETUP_TARGETS_JSON`, each entry contains `managedDeviceId`, `groupId`, `directoryObjectId`, `entraDeviceId` and `serialNumber`. Use a pre-existing static security group with exactly that one device as its only member. `directoryObjectId` identifies the Entra directory object. `entraDeviceId` identifies Windows’ Entra join and must also match the Intune device record. Supply the Entra tenant, app client ID and SHA-256 certificate thumbprint through Railway’s private configuration. Set `CAL_EATS_MANAGED_SETUP_PRIVATE_KEY_FILE` to a protected file or use the sealed `CAL_EATS_MANAGED_SETUP_PRIVATE_KEY_PEM` runtime variable. Keep the private key out of source, logs and installer content. See [the example environment](../.env.example).

The Cal-Eats installer runs as SYSTEM. It checks the Windows BIOS serial and Entra join ID, uses the dedicated Cal-Eats companion and stores its machine key with the existing non-exportable Windows key provider. The script reports a public key and signed setup proof through Intune and exits. The companion finishes the registration asynchronously. The same installed broker then receives signed app access. The expected pilot uses the existing Cal-Eats workspace in Edge. Edge site permission for the local connection must already be granted or allowed by its existing approved device policy. An up-to-date, signed-in workspace can connect when installation finishes. Refresh a workspace already loaded from before this update so it can check in.

## Check a live pilot

1. Verify the location’s orders and printer jobs are safe to leave undisturbed, the tablet’s real Intune identity, its one-device group and any existing Cal-Eats registration. A different existing registration needs the established replacement procedure.
2. Enable the Cal-Eats managed setup connection and check service health. Select and save the exact tablet and location. Observe the new dedicated script assignment, then the exact device’s execution report. The platform will keep waiting while the tablet checks in. A timeout or evidence failure shows **Tablet setup needs attention**. Inspect the dedicated script and device logs, then save the same assignment to retry with the existing job and key.
3. Verify the signed application receipt for the selected app choice. On the physical Surface, check the workspace after switching each permitted mode and verify that the existing printer still works. Check the owner’s Calai approval separately before testing Calai or Both.
4. To stop new managed setup activity, disable the feature flag. An already registered tablet continues to use the established signed Cal-Eats connection. A still-assigned Intune script can run even after the Cal-Eats feature has been disabled. Review and, if needed, unassign only that dedicated script in Intune. Use the existing tablet revocation and physical handoff process for a registered tablet.

Managed setup applies app choices inside the existing business workspace. Windows startup, native Calai deployment and the shared printer continue through their existing setup.
